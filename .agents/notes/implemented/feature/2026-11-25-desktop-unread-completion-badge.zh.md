# Agent Note: 桌面应用图标角标显示未读的轮次完成

Status: implemented

[English](2026-11-25-desktop-unread-completion-badge.md) | 中文

## Problem

会话往往在窗口已隐藏、或用户正在使用其他应用时跑完。唯一的提醒是侧栏某一行上的状态圆点，而用户并没有看那个窗口，因此跑完的轮次很容易被忽略。用户希望应用图标本身就带上这个数字，其他 agent 应用也是这样做的。

[ui-session-status](../../../../packages/client/ui-session-status/README.zh.md) 背后的阅读记录已经知道哪些会话有未读完成，也已经排除可见且聚焦的主视图正在显示的那个会话。因此桌面壳需要的是一个计数，而不是另一套提醒状态的来源。

## Decision

前端通过一条私有 IPC 通道上报列表中最新一次完成仍未读的会话数量，Electron 主进程把它画到应用图标上。macOS 设置 Dock 角标文字，Linux 设置启动器计数，Windows 不绘制，因为 Electron 在该平台没有计数角标接口。Dock 文字在超过 99 后显示 `99+`。

计数来自状态表和工作区展示的会话列表，因此它与侧栏行的提醒一致：读取某个会话（包括在聚焦的主视图中打开它）会降低计数，子 agent 会话从不计入。重新加载插件和窗口销毁都会清除角标，没有桌面桥接的页面不上报任何内容。

## Alternatives considered

**在宿主侧统计完成数。** 宿主能看到每一次 `turn/end`，但它并不知道用户正在读哪个会话，因此要么复制前端的阅读规则，要么把用户已经看过的会话也算进去。

**每次完成都发一条系统通知。** 这需要通知权限，连续多个短轮次时会很打扰，而且与侧栏已经显示的提醒重复。

**在 Windows 任务栏上绘制叠加图标。** Electron 在 Windows 没有计数接口，叠加图标需要为每个数字准备位图。Windows 已有托盘图标，而计数在侧栏仍然可见。

**把待交互请求也计入。** 审批、计划评审和提问有各自的侧栏状态，表示的是被阻塞的会话而不是跑完的会话；两者相加会让这个数字含义不清。

## Consequences

角标是前端基于宿主阅读记录得到的计数，因此同一宿主的两个前端在阅读记录收敛之前可能显示不同的值。用户归档的会话会保留提醒并继续计数，直到被标为已读，因为归档状态是状态包不读取的工作区状态。在存在计数展示方式之前，Windows 不显示角标。没有任何内容进入模型请求，因此不新增会话事件，也不需要更新快照。

验证覆盖上报端（`packages/client/ui-session-status/tests/desktop-badge.client.spec.ts`）与原生角标控制器（`apps/desktop/tests/app-badge.spec.ts`）；在独立 Electron 进程中运行该控制器时，Dock 图标上画出了计数。组装后的应用角标没有自动化覆盖。

# 发布到青狮插件市场

## 准备发布包

1. 找到用户要发布的插件或技能的包目录。核对 `package.json` 中的包名和版本。包名属于 `@qinglion/`，版本使用 SemVer。更新时保留原包名，使用新的版本号。若 `private` 为 `true`，先确认选中的是可独立发布的子包。
2. 插件保留项目实际使用的入口和 DSH 元数据。发布技能时设置 `qingclaw.resourceType` 为 `skill`，保留能向 `ctx.skills` 注册技能的插件入口；入口读取的 `SKILL.md` 和资源须纳入 `files`。用创作模式加载插件，核对技能出现在会话目录。填写用户能识别的显示名和说明。若已有 `publishConfig.registry`，核对它指向青狮私服。
3. 按项目现有脚本构建并运行有关测试。在包目录运行 `npm pack --dry-run --json`，检查文件清单包含清单声明的入口、构建结果及运行所需资源，排除凭据和本机配置。
4. 在包目录运行 `npm pack --json --pack-destination "<已创建的包目录以外的输出目录>"`，将占位符替换为本地绝对路径。根据命令输出的 `filename` 找到实际的 `.tgz`。压缩包上限为 25 MiB。向用户给出包名、版本和可打开的本地文件路径。

## 提交与上架

- 创作者从客户端「左下角账号菜单 → 创作者中心 → 提交插件或技能」选择这个 `.tgz`，点击「提交审核」。管理员的同一入口叫「青狮管理」。普通用户需要先取得创作者角色。
- 管理员从「左下角账号菜单 → 青狮管理 → 插件发布 → 发布审核」核对包名、版本与内容，点击「发布」。官网后端使用服务端 npm 凭据发布到私服，并更新市场目录。创作者本地只需执行 `npm pack`。
- 上架后，在审核列表检查已发布版本。带工作台声明的插件还可在「工作台 → 市场」中验证安装。报告时区分已打包、已提交和已上架，只记录实际完成的步骤。
